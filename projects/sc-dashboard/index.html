Supply Chain P&L Dashboard

A BigQuery + dbt data pipeline feeding a Looker Studio dashboard that gives finance and supply chain teams facility-level, customer-level, and channel-level profitability — down to EBITAI margin — for an EU dairy network, refreshed automatically instead of rebuilt by hand in Excel.

The Business Problem

Supply chain finance teams typically know total cost, but not where it comes from — which facility, which product, which customer is actually profitable once transport, storage, and inventory carrying cost are allocated correctly. That allocation is usually done manually per report, which means it's slow, inconsistent between analysts, and rarely gets down to the order level.

This project replaces that manual process with a single automated pipeline that takes raw ERP-style source tables — facilities, customers, products, transport rate cards, sales orders, internal transfers, and inventory — and produces one profitability record per sales order (about 200k rows), fully allocated down to EBITAI.

What It Enables

  • Executives can filter Sales Value, EBITAI, and margin by country, channel, and date range in seconds instead of waiting for a report cycle.
  • Network planners can see cost breakdown (handling, storage, transport) by facility to spot which sites are structurally expensive.
  • Commercial teams can rank customers and channels by EBITAI margin to find which accounts are quietly unprofitable despite high sales volume.

How the Numbers Get There

The pipeline is layered in dbt: a staging layer that renames raw tables 1:1 with no logic, an intermediate layer that does the actual cost allocation, and a single mart — fct_sales_pnl — that Looker Studio reads from directly.

ModelWhat it does
int_facility_inventory_allocRounds weekly inventory up to whole pallets, averages per facility/product, allocates storage, overhead, and inventory carrying cost by inventory share
int_transfer_costsCombines internal transfers with rate-card and origin handling cost
int_outbound_totalsTotal volume leaving each facility, across sales and transfers
int_inbound_inherited_costsPushes transport, handling, storage, and IOC down to the receiving facility from inbound transfers
int_facility_cost_poolCombines direct and inherited costs into one pool per facility/product

Each sales order's cost share uses a single allocation ratio (its volume ÷ total facility/product volume), applied consistently across every cost type — then the P&L waterfall builds down from there:

GM     = Sales Value − COGS
CBM    = GM − (Transport + Handling + Storage/Overhead)
CBMAI  = CBM − Inventory Carrying Cost
SG&A   = 3.5% × Sales Value
EBITAI = CBMAI − SG&A
